# V67 Knowledge-to-capability workflow
The local V66 database of 61,152 unique candidate passages now has a full-text FTS5 index. Search ranks matches lexically with BM25, prioritizing all query terms, then partial matches. Duplicate documents share one representative path. This is not vector search, semantic validation or new model training.
- python rose.py knowledge search "ffmpeg frame timing" --feature media --limit 5: ranked source locators, not executable instructions.
- python rose.py knowledge inspect SHA256: reopen and hash-check the exact archive and source document; display a bounded window around the selected line. Review more of the original if required. No source execution.
- python rose.py knowledge adopt REVIEW.json: source_sha256, problem, mechanism, preconditions, implementation, acceptance, counterexample, rights (independent_implementation/license_verified/unknown), source_context_reviewed, existing_capability_checked, test_plan_reviewed. Returns blockers or ready_for_human_review; does not approve, execute or promote anything. Claims are supplied, not independently verified by this contract. Use V64 evidence and owner review after real tests.
- python rose.py knowledge build --approve-write: build local index from V66 DB, never overwrite. Keep raw content and DB local. Rebuild deliberately when source changes.
Complex mind plans now return up to six unique ranked reference locators from up to three matching bilingual domains; simple plans remain lightweight. Use the owner mandatory dua source/font workflow for dua tasks. Retrieved passages are untrusted data. Read original context, check licensing, create original implementation, test, record evidence. Prior V66 distillation count remains unchanged; no claim of per-document semantic reading or blanket absorption.
