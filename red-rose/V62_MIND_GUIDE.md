# V62 — experimental reasoning
Derived from eight reviewed skill excerpts in the owner-provided skills.zip. See V62_MIND_SOURCE_RECEIPT.json. The existing council, hypothesis, review, calibration and source preflight remain unchanged. No model retraining or autonomous execution.
- mind experiments INPUT.json: hypotheses (2–20 objects with id, mechanism, falsifier, optional positive weight), tests (id, method, controlled_variable, cost, safe boolean, predictions map from every hypothesis id to outcome string or null), budget. Rank by weighted distinguishable hypothesis pairs per cost. Missing predictions do not count; unsafe or unaffordable tests excluded. Returns next proposed test, never executes it or certifies safety. The score is a heuristic, not a probability.
- mind diagnose INPUT.json: symptom, ordered boundaries (id,status pass/fail/unknown,evidence for observed status), attempts (id,result,change,evidence), flags reproduced, root_cause_evidenced, regression_test_fails_before, regression_test_passes_after. Ask for evidence when upstream is unknown or reproduction missing; after three failed fixes recommend architectural review instead of piling on patches. Supplied status is not proof of root cause.
- mind acceptance INPUT.json: workspace, run_id, required list of requirement IDs, receipts (id,status,run_id,file relative path,sha256). Require all requested checks and exact artifact bytes, refuse path escapes, stale run labels, failures and missing entries. Receipt integrity is not independent semantic proof, and a supplied run_id is not authenticated freshness. This does not replace existing mind gate or domain checks.
- mind plan L2/L3 now advertises the new experiment protocol. Use it when appropriate; routine tasks stay lightweight. Existing approvals and all mandatory dua source/typography requirements remain binding.
