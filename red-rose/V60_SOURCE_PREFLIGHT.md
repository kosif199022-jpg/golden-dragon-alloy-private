# V60 source identity and evidence preflight
Before learning from a downloaded archive, APK, project, document, or media source, establish identity from structure and actual bytes rather than the filename or marketing title. Run python rose.py source-preflight inspect FILE --expect-kind apk --expect-package com.example.editor --expect-sha256 EXPECTED_SHA256 (options independently optional). The command never extracts files, launches the target, contacts services, or examines credentials. It hashes the file twice, checks header, ZIP inventory and limits, rejects traversal, unsafe paths, encrypted entries, symlinks and case-insensitive name collisions; no extraction is done. It reads one bounded binary Android manifest with the local isolated Androguard parser if available. A duplicate normalized name blocks use even if the exact manifest can be read. Identity_candidate is only a provisional identity; it is NOT authenticity, verified signature, content integrity, safe execution or successful media decoding. Unknown/failed results remain unresolved or blocked. Use full FFprobe/decode for media and trusted publisher comparison for signatures separately.
For evidence comparison: python rose.py source-preflight compare RECEIPTS.json --expect-sha256 EXPECTED_SHA256. Supply 2–16 records with method_family, status (observed/failed/partial/not_tested), value, input_sha256, evidence_sha256. Two distinct method labels AND evidence digests with agreeing observed values are only a corroboration candidate. The command does not authenticate the evidence files or independently prove method independence or semantic correctness. Conflicts or any unresolved receipts require review. Never infer absence from tool failure or signature-pattern false positives.
Source lesson from the 2026-11-26 Uptodown 7.46 report: actual application identity differed from filename; direct manifest parsing, archive inventory and prior evidence independently supported the correction. Different tools had partial architecture coverage, decompiler failures and contextual false positives; signature integrity was not proof of official provenance. Reuse the methodology, not the proprietary code, credentials, protected service authentication details, or device telemetry. Do not run, install, upload or contact third-party targets merely to learn from them.
