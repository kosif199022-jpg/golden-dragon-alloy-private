# V61 studio fusion — reference library and native preflight

The owner-supplied skills.zip was indexed without extracting or executing third-party code. 35,564 SKILL.md documents, 35,303 unique byte hashes, 34,396 roots. Categories are filename heuristics (486 media, 471 finance, 3,908 engineering, 1,911 reasoning, 28,788 other); neither categories nor reference counts prove executable capabilities. Selected relevant excerpts inspired original implementations; see V61_SOURCE_RECEIPT.json. No license verification or blanket permission to redistribute source contents.

Use the unified CLI:
- python rose.py studio-fusion find remotion --limit 20 (local metadata only; opens the local SQLite index read-only).
- python rose.py studio-fusion shot JOB.json. Supply identity, setting, style, camera, allowed_seconds (provider/UI choices verified by operator, default [8]), duration, fps, reference_required, reference_id, beats [{seconds,action,speaker,dialogue}], and optional words_per_second/end_hold. Exact user dialogue is preserved. Frame totals, missing reference ID and estimated speaking budget are checked. A blocked plan has no generated prompt. Reference IDs are metadata, not proof of actual asset or identity. Speech rate is an estimate, not audio or phoneme alignment. The resulting prompt does not call Veo or produce a video.
- python rose.py studio-fusion curve CURVE.json with {frames,keyframes:[{frame,value,ease},...]}. Use explicit first/last keys and linear, smooth, ease-in, ease-out. Values sampled deterministically for each frame. Curves are design proposals, not measured source motion; V57/V58 remain the source-replay route.
- On a new machine, build the local index with python build_skills_index_v61.py PATH_TO_SKILLS_ZIP --approve-write. It stores document paths/digests/sizes/category/license labels, not raw instructions; no automatic execution. Keep the original archive private, use actual source inspection before learning and verify license. Existing V60 preflight is for bounded ordinary archives; this large collection was explicitly handled by a dedicated read-only inventory with per-document bounds and whole-archive SHA-256 checks.

Dua/azkar tasks must follow the Mandatory owner rule in references/DUA_REELS_PLAYBOOK.md (verified owner footage, exact source typography, motion and word timing). The generic shot compiler refuses declared dua jobs; use the established dua path. No claims of global runtime enforcement or automatic model learning. Technical QA, visual continuity and actual audio/rights must be checked after real generation.
