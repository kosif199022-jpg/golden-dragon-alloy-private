# V68 cross-source metric reconciliation
Original local read-only arithmetic/definition check based on the reviewed source in V68_METRIC_SOURCE_RECEIPT.json; no vendor requests, journal writes, automatic FX conversion or audit opinion. Complements existing transaction-level accounting_v21.py. Run python rose.py metric-reconcile JOB.json.
Required metric, primary_id, authority_basis, tolerance (explicit decimal string or integer), sources (2-30). Each source has id,value,as_of (timezone-aware ISO),method,evidence (reference text),definition with entity,population,inclusion,period_start,period_end,currency,basis,aggregation. Primary may supply recompute {value,method,evidence}. Other sources may supply components [{label,kind:composition or period_boundary,amount,evidence}]. Component amounts are signed primary minus comparison. All arithmetic uses Decimal; no averages. Different currencies are incomparable. Pre-period-end exports need provisional=true. Nonzero residual or unproven definition differences remain visible. Even complete component arithmetic is only a claimed explanation pending review; evidence references and authority are supplied, not independently verified. review_required means arithmetic/definition review flags; a final certified value is never emitted. Actual ledger/export evidence, query independence and human review are required.
