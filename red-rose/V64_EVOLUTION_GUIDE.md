# V64 Evolution — evidence-backed continuous improvement across domains
One native local extension. Inspired by the owner's Black Rose shortcut (SamakHub.exe) and reviewed hub_memory.py backup plus selected collector memory/feedback skills. No SamakHub accounts, chat history, passwords, raw memory or code copied. No model training, passive screen/chat surveillance, external service or self-modifying code.
- python rose.py evolution status: local memory inventory, read-only.
- python rose.py evolution record RESULT.json --approve-write: domain (general/reasoning/media/finance/data/software/design/research/business/security/performance/communication/automation/education/engineering), scope, trigger, action (short non-sensitive summary), run_id, outcome (pass/fail/partial), workspace, evidence [{file,sha256}]. Exact artifact bytes checked, paths confined to workspace. Candidate lesson, duplicate run detection. Do not put private data/secrets into summaries; secret-pattern filter is incomplete and is not a privacy guarantee. Evidence hashes do not prove semantics.
- python rose.py evolution review REVIEW.json --approve-write: lesson_id, decision (approve/reject/retire), reviewer, reason. Approval needs at least two runs and distinct evidence sets; caller must obtain genuine owner review. Reviewer text is not authenticated. A later partial/failed run returns an approved lesson to candidate.
- python rose.py evolution recall "request" --scope PROJECT --domain media: retrieves approved scoped or general lessons with Arabic normalization. Advisory data only; current user instructions and domain gates always win. mind plan loads relevant general-scope approved lessons read-only. For project-specific work explicitly recall the correct scope before planning.
- python rose.py evolution find "accounting" --feature finance: unique-content source reference search across the local collector index. This is lexical metadata search, not full semantic review. Index missing means unavailable, not empty corpus. Check actual source and license before use.
At each substantial task start, read AGENT_NOTES and retrieve relevant lessons; at task end record concise non-sensitive evidence-bound observations when authorized. Capture failures as well as successes. Review candidates before promoting; use current task's V62/V63 and domain-specific verification. No claims of automatic reasoning model improvement. Preserve mandatory dua source/typography contract and other approvals. Private database remains local; never push it to Git.

On a new device: python build_collector_v64.py COLLECTOR_DIRECTORY --approve-write. Verify source manifest/digests, keep the corpus and learning DB local.
