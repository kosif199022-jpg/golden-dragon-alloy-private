# V69 runtime dua gate and knowledge ranking

Scope: Red Rose V69, branch red-rose-v69-agent based on e83fc96. Do not merge into main. Native read-only gate with explicit, separately approved staging writes. No private media, font binaries, databases or extracted source text in the commit.

## Dua job contract

Run: python rose.py dua-gate check JOB.json. Exit 0 = checked declared inputs; 1 = refused. Does not render or grant write approval. All asset paths must be absolute. Supply kind=dua, clips (ordered [{file,sha256,start,end}], seconds), fonts (map renderer role/file name -> {file,sha256}), audio {file,sha256}, word_timing {file,sha256}, and captions [{text,start,end,word_start,word_end}]. Word indexes are zero-based, end exclusive. The separate timing JSON has audio_sha256, method (whisper_word_timestamps, whisperx_alignment or manual_audio_alignment), and words [{text,start,end}]. No evenly divided estimates. Exact source-byte hashes, media duration, root confinement, caption-to-word mapping and chronology are checked. A method label and hashes cannot prove alignment quality or that an aligner genuinely ran; manually inspect the audio. No automatic ownership/license inference.

Approved roots: ~/.red-rose/libraries/dua-telegram-complete/videos and ~/.red-rose/fonts. Restore the registered fonts-library-v1 release to the latter before use, checking the release/source hashes per DUA_REELS_PLAYBOOK; the gate does not download releases. Missing files fail closed. Unverified outline-only overlays, default system font fallback requests and extra unaligned caption tails are not accepted by the integrated paths. Fast-reel additionally checks actual text cmap coverage using fontTools and refuses missing-glyph fallback; it does not certify shaping, style or rights. V34 checks exact font files, not glyph fidelity.

### Actual renderer bindings
- dua-reel (dua_reel_v34.build): embed the above object as plan.dua_gate; plan.clips must specify the same file/start/end, plan.fonts must specify exact paths for all four roles line/calligraphy/title/latin, plan.audio must be identical, lines [{text,t0,t1}] must match aligned captions. Use shot_plan/shot_plan_cut to determine exact trim lengths; no automatic selection or guessed captions at render time. The golden-native render wrapper forwards the same explicit contract. Storyboards also gate before writing. Existing rendering/quality/approval checks remain. Fade handles are derived from word timestamps, not evenly spaced lines.
- fast_reel/make.sh: WORK/spec.json includes dua_gate; sel.txt and voice.m4a must match it. Each scene needs ss and explicit a/b, source end = ss + (b-a) + .2 + max scene xf (the renderer's actual extraction window). All nine CSS font files and any explicit additional font file must be registered by basename, with exact approved paths. The wrapper checks before staging, copies approved fonts, removes implicit looping and seeking, seals locally extracted JPGs, and render.mjs rechecks the actual staged spec, renderer scripts, fonts and frame hashes before launching Chromium. Captions read verified start/end intervals. Unverified traced overlays are refused. The local seal detects stale/tampered staging, not adversarially forged receipts or independent proof of extraction. Direct old standalone copies of render.mjs are no longer supported. Run from the repo with the same dependencies; the original owner asset tree must be available on the rendering machine. Staging writes require --approve-write. Old generic examples need migration.
- vn-dua-analyze --render-job JOB.json runs the same preflight; vn_dua_v47 is only a read-only metadata analyzer, not a VN renderer. Normal analysis stays available; the external VN application is outside this runtime.
- montage-code preserves V65's refusal of dua; if a dua contract is present it cannot masquerade as general. It checks supplied dua contracts before refusing unsupported dua rendering. General jobs remain supported.

This is enforcement at the named entrypoints, not a system-wide sandbox: arbitrary FFmpeg, separate custom scripts, browser console calls, external editors and falsely declared generic jobs are not automatically intercepted. Keep the mandatory owner rule for every path. File checks do not defend against concurrent changes after validation. Real style/rights/full decode/visual and word timing QA are separate acceptance gates.

## Knowledge search
The existing FTS5 index is compatible; no private database rebuild or upload required. Arabic-English concept groups, exact path/title hits and BM25 weighting (path 12, section 5, excerpt 1) improve lexical retrieval. Search candidate locators only, no raw external instruction or automatic promotion. Inspect source context and adoption/evidence gates unchanged.

Reproduce: python -X utf8 test_knowledge_v69.py --report. Synthetic fixture of 53 short original reference documents, 32 labelled questions (16 English/16 Arabic), expected paths and actual top three in V69_KNOWLEDGE_EVAL.json. Precision@3 = sum correct top-three hits / 96 (missing results count as misses). Before 38/96 = 39.5833%; after 95/96 = 98.9583%. Fixture constructed for this change, not blinded or representative of the 61,152-candidate private corpus. This is not a general semantic accuracy claim. No private DB dependency in new tests. One query still returns a distractor.
