# قياس الراوتر (اختيار الطريق)

أي تعديل في `route()` أو `INTENT` أو `playbooks.json` أو `route_examples.jsonl` يتقاس هنا الأول. `rd.py selftest` بيشغّل التقييم ده لوحده، وبيفشل لو الدقة نزلت عن `floor.json`.

## المجموعتين
| المجموعة | العدد | المصدر | التقييم |
|---|---|---|---|
| old | 101 | طلبات من أرشيف التطبيق (`owner_requests.json`) | 4 مقيّمين عُميان (`labels_1..4.json`، v2.6). اتقيّمت من غير الرسالة اللي قبلها، فـ «كمل» لوحدها = none، **فبتتقاس من غير سياق** |
| fresh | 221 | رسايل صاحب الشغل في جلسات Claude Code المحلية، ومعاها الرسالة اللي قبل كل واحدة (`fresh_cc.json`) | مقيّمين اتنين مستقلين (`labels_fresh.json` و`labels_fresh_b.json`)، اتفقوا على الطريق الأول 86%. الـ best من الأول، والمقبول من الاتنين (`labels_fresh_consensus.json`). **بتتقاس بموضوع المحادثة `--topic`** |

- **dev** = الـ id الزوجي، وده اللي بيتضبط عليه.
- **test** = الـ id الفردي، وده اللي بيتبلّغ.
- test بيتقاس **مرة واحدة** بعد ما القيم تتقفل، ومفيش ضبط بعدها.

## الأوامر
```
python -I -X utf8 mind/route_eval/route_eval2.py scripts --set old   --split dev --calib
python -I -X utf8 mind/route_eval/route_eval2.py scripts --set fresh --split dev --topic --novel --calib --show-misses 20
python -I -X utf8 mind/route_eval/route_eval2.py scripts --set old   --split test --json      # اللي selftest بيشغّله
python -I -X utf8 mind/route_eval/why.py "<طلب>" ["<الرسالة اللي قبله>"]                      # ليه الطريق ده؟
```
- **ذاكرة الأمثلة بتتقاس بأمانة:** طلبات test من المجموعتين مستخبية دايمًا، وفي dev بيستخبى كمان الطلب نفسه وقت ما بيتقاس (leave-one-out).
- `--novel`: بيقيس الطلبات اللي مالهاش شبيه قريب (تشابه ≥ 0.8) في الذاكرة.
- `--calib`: بيقيس الدقة لكل درجة ثقة.

## الأرقام (`floor.json`)
| test: الأول صح / مقبول / في أول 3 | v2.6–2.7 | v2.8.0 | الأرضية |
|---|---|---|---|
| old (من غير سياق) | 52 / 58 / 66 | 66 / 72 / 80 | 62 / 68 |
| fresh (`--topic`) | 23 / 38 / 36 | 59 / 71 / 80 | 55 / 67 |

اتفاق المقيّمين على fresh 86%، وده تقريبًا سقف أي راوتر على البيانات دي.

**بعد تصليح الدردشة والحالة (من التجربة الكاملة):** test اتقاس تاني مرة واحدة للتأكيد. الأول صح والمقبول ماتغيّروش في المجموعتين، و«في أول 3» في fresh نزلت من 81.25% لـ 80.36%، يعني طلب واحد من 112. وdev ماتغيّرش.
- في كل نص: مكسب طلب وخسارة طلب.
- **المكسب:** طلب جديد كان بيتسحب لـ status من سؤال حالة قبله.
- **الخسارة:** رد قصير على الشغل اللي اتسلّم، زي «خلص وحطها في مجلد».

## اختبارات ثابتة
- `../route_tests.json`: طلب ← طريق. والقيمة `none` معناها دردشة من غير طريق.
- `../route_ctx_tests.json`: نفس الفكرة بالرسالة اللي قبلها. فيها `want`، أو `not` (الطريق اللي ممنوع يطلع الأول).
- `_oldtests.py` بيشغّل التلاتة على نسخة الشغل بذاكرة فاضية.

**الأرضية تطلع بس، ماتنزلش:** لو نسخة جديدة قاست أعلى على test، ارفع الأرضية. وماتنزّلهاش عشان نسخة تعدّي.
