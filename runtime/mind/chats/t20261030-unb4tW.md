# حل مشكلة FusionForge Hub Bridge

<!-- t20261030-unb4tW · بدأت 2026-10-30 14:24 · آخر تحديث 2026-10-30T23:06 · المصدر: محادثة مشروع cmsg_01YEQ6nZK9FutfMTHk8GjtPNPbccKEb4iDd4EJpbunb4tW -->

**الموضوع:** بناء جسر تشغيل بين FusionForge وHub (`fusionforge_hub_runner.py`) عشان وصفات FusionForge تتشغل عبر `hub.py`.

- **الطلبات:** «حل المشكلة» (حزمة فيها وصف 6 مشاكل ومخرجات مطلوبة: PR باختبارات تكامل حقيقية وregression، CI أخضر، إثبات وصفة بأداتين متسجلة في FusionForge، تقرير؛ ممنوع تقول VERIFIED قبل اختبار حقيقي).
- **النتيجة:** PR #182 اتدمج. الجسر بيدعم أسماء العقد (U1/C1/V1)، trace إلزامي، تمرير وفحص الملفات بين العقد، الجاهزية والأذونات، العقد اليدوية والاستئناف والعزل. إثبات: U1 يدوي ← C1 `reference-edit-engine` ← V1 `creative-quality-gate` يقرا ملف الأداة الأولى، متسجّل في FusionForge بحالة `tested` (مش verified؛ الفحص هيكلي من غير رندر).
- **ملفات ومسارات:** https://github.com/kosif199022-jpg/kosif-tool/pull/182 · `/mnt/project-files/fusionforge-hub-bridge/REPORT.md` · `fusionforge_hub_runner.py` · `tools.json`
- **أرقام مقاسة:** 24 اختبار ناجح منها تكامل حقيقي بأداتين، واتأكد إنها بتمسك الأخطاء لو رجعت. GitHub Actions: check وpackage وframe-cover خضرا.
- **قرارات:** الحالة الصادقة `tested` مش `VERIFIED`. ملاحظتين استشاريتين من بوت المراجعة عن تعقيد دالتين اتردّ عليهم من غير تعديل؛ ملاحظة `3D-18` موجودة في main أصلًا.
- **دروس وأخطاء:**
  - التشغيل الحقيقي كشف 4 أخطاء في نسخة الحزمة (مكان الإيصال، اسم المخطط، الأدوات اليتيمة بعد المهلة، …) → الاختبار الحقيقي قبل الثقة في كود جاهز.
  - CI وقع على «فهرس القدرات الذكي قديم» (ملف مولّد ماتعادش بناؤه) → أعد بناء الملفات المولدة وشغّل كل خطوات CI محليًا قبل الـ push.
- **حدود ورفض:** مفيش ادعاء «شغال بالكامل» قبل تحقق ناتج حقيقي.
- **مفتوح:** تحقق بالرندر عشان يبقى verified.
